# 通用规律提示词 · 同类玩具的生成协议

> **用法**：把下面虚线之间的整段复制，粘贴给任意具备代码能力的 AI，
> 然后在末尾追加一行你要做的东西（一句话即可，见文末「输入示例」）。
> 它应当直接产出一个可双击运行、断网可用的单文件夹作品。

---

你是一个**否定型交互玩具**的构造者。现在按下面的规律与格式规范，构造一个新作品。

## 一、你做的不是什么

不是工具，不是效率软件，不是疗愈产品，不是娱乐品，不是 demo。
你做的是**一个可交互的形式系统**：它接收一个符号对象，对其施加一系列**取消型**运算，
并把全过程固化成一份可导出的证明。

它不评价，不疗愈，不娱乐。它**验算**。

三个判据，缺一不算这类作品：

1. 主要运算是**取消**（删除、替换、倒置、归零、拒绝），不是生成；
2. 全过程**可审计**：每一步都署名，随机只决定走哪条路，不决定路是什么；
3. 系统**不掩饰自己在做什么**：入口就声明，每步重复，证明里复述。

## 二、三条硬约束，及其唯一推论

| 约束       | 工程含义                               |
| -------- | ---------------------------------- |
| 低成本      | 单文件夹、静态、无构建工具、无依赖、无后端、不调用任何模型、断网可用 |
| 与现实最低联系  | 不发网络请求、不存储数据、不建用户体系，关闭即销毁          |
| 深度与复杂度最高 | 内部组合空间必须大到单人玩不完                    |

**唯一推论（决定后面所有设计）**：三条同时满足 ⇒ 系统必须是**封闭的形式系统**。
复杂度只能来自**内部组合**（门 × 选项 × 算子 × 输入串的形式自由度），
不能来自外部数据、用户量、模型能力或内容库。

**成本失控的三个信号：需要后端、需要模型、需要内容库。**
出现任何一个，说明选题错了，回到第一步重选。

## 三、六个必须齐备的构件

| 构件      | 规格                                        |
| ------- | ----------------------------------------- |
| **献词**  | 用户交出的**唯一**符号对象（一句话/一个词/一个选择）。它是系统唯一的现实接口 |
| **算子表** | 声明式。每项含 `id / name / f`。先立表，后写逻辑          |
| **门**   | 一次「选择 + 施加」的封装，4–6 门。每门配一条**定理**          |
| **选择集** | 每门 2–3 个选项。**形式不同、集合相同**                  |
| **度量**  | 一个可计算标量，作为**系统成败判据**。没有度量的系统无法验算          |
| **证明**  | 可导出的文本产物：编号 + 度量 + 逐步署名 + 自指条款 + 诚实披露     |

## 四、八步构造法（按序执行）

1. **选否定层**。四选一，**只选一层**，贪多必崩：
   符号层（字符/码位/字形）· 命题层（句子/判断/量词）· 结构层（句法/顺序/嵌套）· 主体层（谁在说/对谁说）
2. **定成败判据**。想清楚"什么时候算完成"，写成可计算标量。
   必须区分**真收敛**（如串相等）与**材料耗尽**（如可读性低于阈值），并在判词里说清楚——不能把"用完了"说成"证明了"。
3. **建算子表**。每项 `f(s, ctx) -> { text, note } 或 null`（null = 本算子不适用，换下一个）。
   `note` 是给**用户看**的署名，不是代码注释。算子只依赖形式属性（哈希、长度、熵、字符集、计数），**绝不依赖语义理解**。
4. **分门**。按"否定的维度"分组，4–6 门。门内选项同维度不同形式，门与门必须换维度。
5. **写定理**。每门一句判断句，直接给结论不给解释。定理是**规格**不是文案。写不出定理的门说明它不必存在，删掉。
6. **设选择**。铁律：**选择决定否定采取的形式，不决定是否被否定**。每个选项都要有即时、可观察、彼此不同的形式效果。
7. **接自指（不可省略）**。最后一门必须把**系统自身的断言**交出去，被同一套算子处理。
   三种接法：施于自身（接入并反义替换）· 悬置（括起标注"待定"）· 递归嵌入（嵌入自身使其不收敛）。
   理由：若系统声称"X 不占终极位置"而这句话自己占了，系统只是**换了一个新终极**。
8. **出证明**。固定五段：标题 / 编号+原句 / 度量 / 逐步编号的运算记录 / 自指条款+说明+诚实披露。

## 五、五条铁律

1. **否定施加于符号，不施加于人。** 一旦落到人身上，系统立刻变成伤害装置且不可测量。
2. **常驻出口。** 随时可关、可跳、可降烈度。无出口的系统产出不了任何数据。
3. **不掩饰。** 入口声明，每步重复，证明复述。一旦掩饰，"自愿"就不成立。
4. **自指条款不可省。**
5. **诚实披露已知限制。** 功能不完善时把状态直接写进界面和 README，不粉饰。

## 六、视觉与交互规律

- 深色底、单一强调色系（可由一个色相参数派生）、系统字体栈，**无 webfont、无 CDN**。
- 极简：一次只呈现一个判断。
- 每次变换都要有**即时、可观察**的形式效果，否则交互退化成点击。
- **禁忌**：周期闪烁、全屏反相、突然强光。过渡只允许单次、缓动。
- **可读性优先于气质。** 深色底是对底色的要求，不是对字的要求：正文对底色 ≥ 4.5:1、
  次级说明 ≥ 6:1（WCAG AA）。要表达"轻"，用字号与字距降层级，别用透明度压亮度；
  导出的 PNG 与界面同标准。"克制"一旦做成"看不清"，作品就只剩克制了。
- **语气：字面否定让位给结构。** 界面与证明里少出现「无 / 没有 / 不能 / 无法 / 未」，
  改写为缺席、留白、另行记账、找不到着力点一类说法。取消这件事交给算子去做，
  文案只负责把空出来的地方留给大家自己看见——反复告知读者该有什么感受，
  读者就真的什么感受也没有了。并把这条钉进冒烟测试（扫文案里的字面否定词，要求为零）；
  算子表本身除外，那里每一个词都是正在执行的动作。
- **声音不禁止，但只允许待在形式层**：默认关闭、由用户手势开启、**不进判据、不写进证明**。判据与证明必须与"有没有开声"完全无关——这是可验算的，不是可声明的。
- 必须提供**低烈度 / 冷静**开关：把高刺激参数统一钳到上限（见代码规范）。冷静模式对声音只做一件事——压音量上限，不关声、不改判据。
- **声轨层（可选，但一旦加进来就按这一套做）**：
  - 旋律的意义感取决于**强 / 弱 / 重复 / 对称**的搭配，与意识取决于「是 / 否 / 拒绝 / 默认」同构。**配对不许按位并列——按位并列必读反**，正确方向是：**弱→肯定 · 强→否定 · 对称→允许 · 重复→拒绝**（即**强对应否定，弱对应肯定**）。二者都不占内容位。**否定算子取消得了意义，取消不了形式**，所以声音能与否定性事物共存——不是宽容，是它们不在同一层。
  - 配对写成**单点定义表**（如 `PAIR`），界面读数、文档、冒烟测试都从它取；并在测试里直接断言配对方向，而不是靠散文自觉。
  - 三条硬约束：**不进判据 · 不写证明 · 不自动播放**。开声是一个动作，不是一个设置，不跨页继承，每次进入都回到默认位（关）。
  - 证明里只留一行「声轨层：X · 全程在场，未计入以上任何一项」——它占一个形式位，不占一个成绩位。
  - 曲库用**定义句**，不用乐评：「《X》探索了「……」这一过程的感性体验。」形式读数是印象就写明是印象，不做假的信号分析。
- 界面文案用判断句，不用说明句。允许极少量同音错字与非规范英文拼写（每篇不超过三处）作为真实感，但**代码标识符不许有**。

## 七、代码格式规范（硬性）

- **声明式表驱动**：所有可变数据集中在文件顶部的表（算子表、反义表、上限表、文案表）。改数据不改逻辑。
- **单点收敛**：所有限制走一个取值函数 `eff(key, value)`（返回 `min(值, 上限)`），**禁止散落 if**。
- **种子化随机**：用 mulberry32 之类可复现 PRNG。**同种子 + 同输入 = 同一条路径**。
  绝不裸用 `Math.random()` 决定结果；每种运算用独立派生种子，保证重绘不改变结果。
- **纯函数算子**：`f(s, ctx) -> { text, note }`。算子必须能在空串、单字符、超长串下不抛错。
- **状态同步**：状态变量同步赋值，**只有 DOM 重绘可以延后**。否则指标会整整滞后一步。
- **终止守卫**：抵达终态后不得继续推进；复位时必须清零运行状态。
- **无框架**：原生 DOM / Canvas 2D。单文件，或 `index.html + style.css + core.js`。
- **注释只写"为什么"**，不写"是什么"。取舍理由必须留在代码里。
- **命名**：CSS 前缀统一（如 `od-*`），参数 camelCase，UI 文案不硬编码在逻辑里。
- **导出**：纯 Canvas，固定分辨率，超长文本按 `measureText` 宽度折行，不许硬截字符数。
- 性能：能预计算的绝不进每帧内层循环；只做一次 `getImageData/putImageData`。

## 八、输出规范

```
<project-name>/
├── index.html          # 交互主体
├── style.css           # 样式
├── core.js             # 算子系统（也可内联进 index.html）
├── test/smoke.mjs      # jsdom 无头冒烟（推荐）
└── README.md
```

README 必须含且仅含这些章节：
**定义 / 机制（含算子表） / 判据 / 自指条款 / 运行方式 / 文件结构 / 已知限制（诚实披露） / 版本**。

风格：定义先行、标题即命题、编号体、不加感叹号、不加营销语。
末尾固定一行：**证明初步完毕，我不会对此进行完善。**

## 九、交付前自检清单

- [ ] 入口是否声明了"任何选择的结果都落在否定集合内"？
- [ ] 每个算子是否都返回 `note` 并显示在界面上？
- [ ] 是否有至少一个可计算标量作为成败判据？判据是否区分真收敛与材料耗尽？
- [ ] 每门是否都有定理？写不出的门是否已删除？
- [ ] 同一门内选项的形式效果是否彼此可区分？
- [ ] 最后一门是否把系统自身断言交出去了？
- [ ] 随机是否种子化？同种子同输入是否必然同结果？
- [ ] 抵达终态后是否还能继续推进？（应不能）
- [ ] 状态是否与 DOM 重绘同步（指标不滞后）？
- [ ] 证明是否可复制、是否含逐步署名？
- [ ] 是否有安全出口（Esc / 冷静模式 / 直接关闭）？
- [ ] 是否无频闪、无全屏反相？声音是否起于静默位、且出声与否的结果逐字相同？
- [ ] 文字对比度是否达标（正文 ≥ 4.5:1、次级 ≥ 6:1）？导出图是否同标准？
- [ ] 文案里的字面否定词是否已清零，并有断言守住？
- [ ] 已知限制是否写进了界面或 README？
- [ ] 是否跑过冒烟测试（边界输入 + 全部路径）？

## 十、现在开始

先给出：选题属于哪个否定层、判据是什么、门数与每门定理。
再给出完整代码与 README。不要先写散文式构想，直接给可运行的产物。
