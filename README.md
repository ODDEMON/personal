# ODDEMON · 四件离线玩具

四个可离线运行的小作品。共同规则：**断网可跑，数据留在你的窗口里**——联网、上传、后端、埋点一概缺席。
否定施加于符号，施加不到人身上；全过程可审计，痕迹自带。

**两条视觉与语气上的约定**，四件作品共用：

- **可读性**：底色是夜色，字是亮的。所有文字按 WCAG AA 校准过（正文 ≥ 4.5:1，次级说明 ≥ 6:1），
  改暗时请连带校准对比度，别让"克制"变成"看不清"。
- **语气**：界面与证明里少写字面否定词（无 / 没有 / 不能 / 无法）。否定交给结构去演，
  字面一律让位——反复告知读者该有什么感受，读者就真的什么感受也没有了。
  这条已钉成断言（见 §四）：改文案时它会先跳出来。

## 一、总台与归档协议

根目录的 `index.html` 不只是目录页，它是**总台**：发号、收档、然后在三份回执都到齐时给一句总判。

1. **编号与种子同源。** `CASE = OD-<seed 的 36 进制>`。编号是种子的另一种写法，外部那层身份省略，反过来能解回同一个种子。
2. **下发。** 点进任一作品，链接自带 `#case` 与 `#seed`。作品读出来、写进自己的证明——三份证明因此在同一编号下可互相复算。
3. **回收。** 作品结束时点「⤤ 归档至总台」，把一句判词摘要塞回 `#rec` 交还总台。总台只收摘要，不收全文。
4. **自指。** 三份齐了才出总判，而总判正文**已按本协议第六门处理**——你读到的是否定之后的残留。
   本页只发号、只收档；谁要把这句话当成结论，那它同样已被处理。

全程只走 URL，不落任何存储；卷宗另存一份到浏览器本地存储以便刷新后还在，`file://` 下若被收走则退回「只在本次会话里停留」，页面里如实写明。

键盘 `1` `2` `3` 可直达三件作品。

**声音（2026-10 撤掉的那条约束）**：总台与三件作品都带一层声轨，共六首，**起于静默位**。
它只在形式层活动——判据之外、证明之外：同一句话、同一个种子，出声与否，得到的证明**逐字相同**。
原先写的是「无声音」，那条约束在 2026-10 撤掉了，撤掉的理由写在 [`bgm/声轨层.md`](bgm/声轨层.md)。

**协议之外**另有一栏：`oddemon-typo`。介绍与引用照给，只是**不发号、也不收档**——它跑在一个本地服务里，本页递不到编号。总台只收能在同一编号下互相复算的证明，这是一条边界，写在界面上，谁都读得到。

## 二、三个纯静态作品：下载后直接打开

`game/`、`proof/`、`the-visitor-protocol/` 三个作品**不需要任何安装**：

1. 下载并解压
2. 双击 `index.html`（或拖进浏览器）

它们不使用 ES 模块、`fetch`、CDN 或任何构建步骤，因此 `file://` 协议下也能完整运行。
也可以直接开 GitHub Pages：仓库根目录的 `index.html` 就是总台入口。

单独打开也能跑——只是没有总台编号，作品会自己临时造一个（`P-` / `V-` 开头）。这不影响任何机制，只是那份证明不再与别的证明互认。

- `game/` —— 鼠标控一点走羊肠小道，擦壁的代价是一次改写：**命题被施加否定算子**，然后退回存档点。六道逐道收窄，走到终点只领一张证明。
- `proof/` —— 输入一句话，交给否定算子一路推到不动点。同种子必得同结果，可复现；`seed` 写在界面上，可自行核对。
- `the-visitor-protocol/` —— 六道门，每门三个选择。**选择只定下否定的形式**，否定本身留在原处。最后一门把协议自己的断言交出去——否则它会变成新的终极。

## 三、oddemon-typo：一键启动

这是唯一需要 Python 的一个（Gradio 只用来起一个本地服务，渲染全在浏览器端完成）。

要求：**Python 3.10+**，且装有 gradio。若解释器里已经有 gradio，启动器**直接跑 `app.py`**——不建虚拟环境、不下载、不重装；没有才会建 `.venv` 装一次。

```bash
# Windows
#   双击 start.bat

# macOS / Linux
chmod +x start.sh && ./start.sh
```

**用哪个 Python**（命中即止）：`PYTHON_EXE` 环境变量 → 同目录 `python.txt`（一行完整路径）→ PATH 上的 `python` → Windows `py`。
`python.txt` 是本机覆盖项，已 gitignore。PATH 上混杂了多个 Python（比如 msys64 那个）时，写这个文件或设环境变量即可钉死。

也可以手动：

```bash
cd oddemon-typo
python -c "import gradio"                    # 有输出即已装好，直接下一步
python app.py                                # 否则先 pip install -r requirements.txt
```

启动后打开 <http://127.0.0.1:7860>。端口被占用时会自动顺延到 7861、7862……（也可自行指定：`PORT=8080 python app.py`）。

依赖只有一个：`gradio>=6,<7`（见 `oddemon-typo/requirements.txt`，实测 6.27.0 / 6.29.0）。

## 六、声轨层：为什么否定不了旋律

旋律是逻辑带来的直观感受的展现。它的意义感与意识一样取决于搭配，两组都是纯形式关系，都不依赖所指。
配对**不许按位并列**（强／弱／重复／对称 对 是／否／拒绝／默认 读出来就是错的），它按《一种理解一切的方法》坐标系的四个极点走：

| 形式上（旋律侧） | 意义上（意识侧） | 坐标系位置 |
| --- | --- | --- |
| 弱 | **肯定**（是） | 上极 |
| 强 | **否定**（否） | 下极 |
| 对称 | **允许**（默认） | 左极 |
| 重复 | **拒绝** | 右极 |

**强对应否定，弱对应肯定——这两个当心读反。** 读反了整套同构照样自洽，这才是它危险的地方。
这张配对在 `bgm/bgm.js` 里有唯一出处（`PAIR`），界面读数、文档与冒烟测试都从它取。

因此旋律**仅在形式上有效**：它不主张任何东西，也就不占据任何可被否定的位置。
否定算子取消得了意义，取消不了形式——你把一段排布改写之后，剩下的仍然是一段排布。
这就是它能与否定性事物共存的全部理由：**不是宽容，不是互补，是它们根本不在同一层。**

落到机制上是三条：

1. **判据之外。** 出声与否、音量高低、听的是哪一首，都落在任何一项计算之外。
2. **证明之外。** 证明里只有一行「声轨层：某曲 · 全程在场，另行记账」——那是它的形式位，不是成绩位。
3. **起于静默位。** 每次进入都回到静默位。出声是一个动作，不是一个设置，它不跨页继承。

六首曲目（定义句，不是乐评）见 [`bgm/声轨层.md`](bgm/声轨层.md)：
`Before` · `Finalism shapes` · `Halcyon` · `Hope of Neutral` · `Say it` · `Silver endings`。
音频文件放在仓库根目录，`bgm/bgm.js` 按自身位置反推仓根去取——**单独拷走某一件作品会丢失声轨**，
此时曲目区空白，不做补足。四值读数（强→否定 / 弱→肯定 / 重复→拒绝 / 对称→允许）是听觉印象，**不是信号分析**，这一点不掩饰。

## 七、如果打不开

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 双击 HTML 没反应 | 关联到了别的东西 | 右键 → 打开方式 → 选浏览器 |
| `start.bat` 一闪而过 | 没装 Python，或没勾 "Add python.exe to PATH" | 重装 Python 并勾选该项 |
| `pip install` 超时 | 网络问题 | 换源：`pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple` |
| 7860 打不开 | 端口被占 | 看启动窗口实际打印的端口号（会自动顺延） |
